# ∅ — absolutely nothing

Single-page experience: interactive dark canvas, light-bulb cursor spotlight, hourglass countdown to **01.08.2026**, email capture, and Solana wallet linking via Supabase.

## Features

- **∅** brand hero, particle + constellation background (mouse-reactive)
- Hidden watermark **01.06.26** (`opacity: 0.04`)
- Background code snippets revealed only inside the cursor spotlight
- Light-bulb cursor with radial torch glow
- Canvas hourglass — sand drains proportionally from **01.06.2026** → **01.08.2026**
- Email form → `subscribers` table
- Solana wallet connect (Phantom / Solflare — Wallet Standard, same flow as `@solana/wallet-adapter-react`)
- X link → [@absolutlynthsol](https://x.com/absolutlynthsol?s=11)

## Local setup

```bash
cp .env.example .env
# Fill SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SECRET_KEY

npm install
npm start
```

Open `http://localhost:3000`. Health: `http://localhost:3000/health`.

## Supabase

1. Create a project at [supabase.com](https://supabase.com).
2. Run `supabase/schema.sql` in the SQL editor.
3. Copy **Project URL**, **anon key**, and **service_role key** into `.env` / Render env.

| Render / `.env` key | Supabase dashboard |
|---------------------|-------------------|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon public |
| `SUPABASE_SECRET_KEY` | service_role (secret) |

The browser loads keys from `/config.js` (generated by the server). Writes use the anon client first; the server API (`/api/subscribe`, `/api/wallet`) uses the secret key as fallback. Duplicate emails / wallet keys return success with `duplicate: true`.

## Render deploy

1. Push to GitHub.
2. Render → **New** → **Blueprint** → select repo.
3. Set env vars: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SECRET_KEY`.
4. Deploy; health check path `/health`.
